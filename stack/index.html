Dependencies and pipeline

What the wallet is built on, and what happens to a change before it lands.

  • React Native
  • GitHub
  • gitworkshop.dev
CodeRabbit reads every open pull request and leaves the comments on that pull request. A person still merges. The review is a second pass. It is not an audit, and it does not sign a release.

Wallet

Keys, descriptors, and transaction building go through Bitcoin Dev Kit (BDK). That is a shared Rust wallet library, the same class of code other Bitcoin wallets already run, instead of a private implementation of descriptors and PSBTs.

The app around it is React Native. You can read both layers in the repository.

Review

Open pull requests on GitHub are read by CodeRabbit before anyone is expected to merge them. The model comments on the diff in public. You can see what it flagged, and what the author answered, without trusting a summary on this site.

That pass exists because a tired reader skips lines. It runs on the change itself: naming, control flow, and the places a wallet diff usually goes wrong. It also comments on style. Ignore those. The useful part is a record that stayed attached to the diff.

What you can check

  • Source on GitHub and the ngit mirror
  • Open pull requests, including the review comments
  • Security policy for reports that should not be public issues
  • MIT license in the repository

What this does not mean

A model review does not make the app safe to hold funds you cannot afford to lose. It misses bugs. It cannot see a compromised maintainer key, a bad release build, or a dependency that was fine when it was pinned and wrong later. Trust the parts you can re-read: the BDK boundary, the public diff, and who merged it.
